# RB-03 — Split the manifest genres: `llms.txt` vs `AGENTS.md`

**KPIs affected:** K2/K3/K4 (`sdk` mode), K10 (drift gates must be updated in the same pass)
**Depends on:** RB-01 for measurement
**Touches:** all 5 SDK repos + `accumulate-studio` + the generator + the drift checks

---

## Why

The five `AGENTS.md` files are good documents filed under the wrong name.

Each is 33 lines, generated by `renderAgents()` in `scripts/generate-agent-artifacts.mjs:211-248`, and contains: the golden path, amount-scaling rules, the operation list, and a pointer to `llms-full.txt`. That is **SDK usage guidance** — which is precisely what `llms.txt` is for. The two files currently overlap heavily and neither does the job `AGENTS.md` exists to do.

The AGENTS.md standard is a *repo* manifest: how to build, test, lint, and navigate **this checkout**. Its four canonical sections are Build & Dev Setup, Test & Validation Commands, Architecture & Style, and Tool/Command Permissions. The current files contain none of them.

Concretely, an agent asked to fix a bug in `opendlt-python-v2v3-sdk` today reads `AGENTS.md`, learns how to *call* the SDK, and still does not know:

- that the repo root `pyproject.toml` declares `name = "accumulate-client"`, `version = "0.0.0"` — a stub — while the real package is `accumulate-sdk-opendlt` v2.2.1 in `unified/pyproject.toml`;
- that root `pytest.ini` sets `testpaths = unified/tests` with `--import-mode=importlib`;
- that `unified/` is the actual project root.

That is a 20-minute detour for a human and a failed task for an agent. Every repo has an equivalent trap.

**And the worst gap: `accumulate-studio` has no `AGENTS.md` at all.** The monorepo that *generates* them for the other five has none. It is the most complex repo of the six — 3 apps, 4 packages, npm workspaces, 24 root scripts, and a Python proxy that must be running for parts of the system to work.

## Verified current state

| Repo | `AGENTS.md` location | Real project root | Build | Test | Lint |
|---|---|---|---|---|---|
| Python | `unified/AGENTS.md` | `unified/` | `pip install -e .` | `pytest` (root `pytest.ini` → `unified/tests`) | `ruff` (`[tool.ruff]` in `unified/pyproject.toml`) |
| Rust | `unified/AGENTS.md` | `unified/` | `cargo build` | `make test` / `make ci-check` | `make lint`, `make fmt-check` |
| Dart | `unified/AGENTS.md` | `unified/` | `dart pub get` | `dart test` (root `dart_test.yaml`) | `dart analyze` (`analysis_options.yaml`) |
| C# | `AGENTS.md` (root) | root, `Acme.Net.Sdk.sln` | `dotnet build` | `dotnet test` (3 test projects) | analyzers via csproj |
| JS | `javascript/AGENTS.md` | `javascript/` | `npm run build` (tsc) | `test:unit` / `test:integration` / `test:all` | `npm run lint`, `code-check` |
| Studio | **none** | root (npm workspaces) | `npm run build` | `npm test` | `npm run lint`, `npm run typecheck` |

Rust ships a `Makefile` with a full target set — `fmt`, `fmt-check`, `lint`, `test`, `test-unit`, `test-integration`, `test-conformance`, `coverage`, `coverage-gate`, `audit`, `ci-check`. **None of it is mentioned in the Rust `AGENTS.md`.** An agent will reach for bare `cargo test` and miss `ci-check` entirely.

## Design

### The split

| Content | Destination |
|---|---|
| Golden path, amount scaling, prerequisite chain, canonical client, operation list | `llms.txt` / `llms-full.txt` — **consumer** docs |
| Build, test, lint, layout, gotchas, permitted commands, PR expectations | `AGENTS.md` — **contributor** docs |

`llms.txt` already carries most of the consumer content (`renderLlms`, `generate-agent-artifacts.mjs:113-149`). The rules block from `renderAgents` (`:229-234`) is the part worth preserving — move it into `llms.txt` under a `## Rules` heading, and delete `renderAgents` in its current form.

### The new `AGENTS.md` template

Sections, in order:

1. **What this repo is** — one paragraph, including the *real* project root if it is not the checkout root.
2. **Setup** — exact commands, with toolchain versions (`net9.0`, Dart `>=3.3.0 <4.0.0`, etc.).
3. **Build**
4. **Test** — including which suites need network access. This matters enormously: an agent that runs the integration suite with no testnet will read failures as its own bug.
5. **Lint & format** — with the exact command that CI runs.
6. **Layout** — directory map, 5-10 lines.
7. **Gotchas** — the repo-specific traps. This is the highest-value section and the only one that cannot be generated.
8. **Permitted commands** — what an agent may run unattended vs. what needs a human (publish, release, anything touching mainnet).
9. **Before you commit** — the one command that must pass.

### Generated vs. hand-authored

Sections 2-6 and 8-9 are derivable from each repo's config and belong in the generator. Sections 1 and 7 are per-repo prose and belong in a new `REPO_META` block in `generate-agent-artifacts.mjs` alongside the existing `LANG_META` (`:34-86`).

This keeps the "nothing is hand-maintained per language" property the generator's header docstring claims (`:11-13`) while allowing the gotchas that make the file worth reading.

### Nested manifests for `accumulate-studio`

The monorepo needs more than one:

| Path | Why |
|---|---|
| `/AGENTS.md` | workspaces, the 24 scripts, proxy dependency, build ordering |
| `packages/codegen/AGENTS.md` | the Handlebars traps — lazy `Handlebars.compile`, the `}}}` adjacency gotcha, `isVarRef` per-language semantics, snapshot regeneration |
| `apps/mcp-server/AGENTS.md` | esbuild bundling constraint (no runtime `fs`), permission model invariants, stdout-is-protocol / log-to-stderr rule |
| `apps/sdk-proxy/AGENTS.md` | Python service, separate toolchain, credit ×100 scaling boundary |

The stdout rule is a real hazard worth stating explicitly: `index.ts:300-315` logs to stderr *because stdout is the MCP transport*. An agent adding a `console.log` will silently corrupt the protocol stream.

## Steps

### 1. Add `REPO_META` to the generator

Keyed by language, with `repoRoot`, `projectRoot`, `setup[]`, `build`, `test[]` (each `{cmd, needsNetwork}`), `lint[]`, `layout[]`, `gotchas[]`, `permitted`/`forbidden`, `preCommit`.

### 2. Rewrite `renderAgents` → `renderRepoManifest`

Emit the 9-section template. Delete the golden-path/operations content from it — that is `llms.txt`'s job now.

### 3. Fold the rules block into `renderLlms`

Add `## Rules` to `renderLlms` carrying the four bullets currently at `:230-233` plus the canonical-client bullet at `:234`. That bullet interpolates `m.entrypoints[0]?.symbol`; keep that dynamic reference.

### 4. Author the studio manifests by hand

The four studio files are not manifest-derived — write them directly. They are not emitted by `generate-agent-artifacts.mjs` (which only knows the 5 SDK languages, `:31`).

### 5. Update the drift gates — **do not skip this**

This is where the change bites. `AGENTS.md` is a *distributed artifact*: `--dist` writes it into each SDK repo (`:288-296`). Changing its shape means:

- **`tools/artifact-verify/verify.mjs`** — check whether any assertion reads `AGENTS.md` content. If it only checks presence, no change; if it checks structure, update expectations or K10 goes red.
- **`scripts/check-manifest-drift.ts`** — validates manifests against the block catalog. Adding `REPO_META` should not affect it, but run `npm run validate:manifests` to confirm.
- **Regenerate and redistribute**: `npm run gen:agent` then `npm run gen:agent:dist`, then commit in all 5 SDK repos.

Do the generator change, the regeneration, and the gate update **in one commit per repo**. A half-applied split leaves some repos with consumer-genre `AGENTS.md` and some with contributor-genre — worse than either.

### 6. Consider `llms.txt` at each repo root

Currently `llms.txt` ships next to the code. Agents also look for `/llms.txt` at a domain root. That is Phase 4 hosted-docs work; note it here and leave it.

## Acceptance criteria

- [ ] All 6 repos have an `AGENTS.md` whose sections are Setup / Build / Test / Lint / Layout / Gotchas / Permitted / Before-you-commit
- [ ] Every command listed has been executed and verified to work from a clean checkout
- [ ] Each repo's *real* project root is stated where it differs from the checkout root (Python, Rust, Dart, JS)
- [ ] Rust manifest documents the `Makefile` targets, including `make ci-check`
- [ ] Python manifest documents the root-`pyproject.toml`-is-a-stub trap
- [ ] Network-dependent test suites are marked as such in all 6
- [ ] `accumulate-studio` has root + `packages/codegen` + `apps/mcp-server` + `apps/sdk-proxy` manifests
- [ ] MCP manifest documents the stdout-is-protocol rule and the esbuild no-runtime-`fs` constraint
- [ ] `llms.txt` gains the `## Rules` section; no rule is lost in the move
- [ ] `npm run gen:agent` reproduces every generated file byte-identically (no hand edits to generated output)
- [ ] `npm run verify:artifacts` and `npm run validate:manifests` pass; K10 stays green
- [ ] Fresh-agent smoke test: point an agent at each repo with only `AGENTS.md` and ask it to run the test suite; it succeeds without exploration

That last criterion is the actual test. Everything else is proxy.

## Risks

**Losing content in the move.** The rules block is load-bearing — `1 ACME = 1e8` is the most valuable sentence in the corpus. Diff old vs. new rendered output and confirm every rule survives somewhere.

**Stale commands.** A manifest listing a command that does not work is worse than no manifest, because the agent trusts it. Execute every command before writing it down.

**Distribution skew.** Five separate repos must each receive the regenerated file. `--dist` skips silently when a path is missing (`:293-294`). Check the output for `dist SKIP` lines.

## Rollback

The generator change is revertible; regenerate and redistribute to restore the previous form. Studio's hand-authored manifests are new files — deleting them is clean.

## As-built (2026-07-27)

Implemented; all six repos now carry a true repository manifest, and the five SDK repos received the regenerated artifacts.

**Delivered:**

- `REPO_META` added to `scripts/generate-agent-artifacts.mjs` — per-repo toolchain, setup, build, test (with a **needs-network** column), lint, layout, gotchas, permitted commands, and a pre-commit gate.
- `renderAgents` replaced by a 9-section repo manifest. Usage content moved to `llms.txt` under a new `## Rules` heading.
- **Studio's four manifests hand-authored**: root, `packages/codegen`, `apps/mcp-server`, `apps/sdk-proxy`.
- Regenerated and distributed to all 5 SDK repos with **zero `dist SKIP`**.

**Verification:**

- All 5 rules survive the move — confirmed present in every `llms.txt`, none stranded in `AGENTS.md`.
- Regeneration is **byte-identical** on a second run (hashed the whole tree).
- Every documented command verified to exist: Rust's 8 `make` targets, JS's 7 npm scripts, Python's `[project.optional-dependencies]` and `[tool.ruff]`, C#'s two test projects, Dart's and Python's `integration` test directories, and all 23 npm scripts referenced by the studio manifest.
- `validate:manifests` and `validate:canonical` both PASS; K10 stayed green.

### Findings recorded in the new manifests

- **Python:** the repo-root `pyproject.toml` is a stub (`accumulate-client`, `0.0.0`); the real package lives in `unified/`. Now stated explicitly.
- **Rust:** the `Makefile` has 8 targets including `ci-check` (fmt-check + lint + test + coverage-gate + audit) that the old manifest never mentioned. An agent reaching for bare `cargo test` skips the coverage gate and the audit.
- **Dart:** pub.dev reports `has:error` at 40/160 — surfaced by RB-07A and now documented as a gotcha.
- **MCP server:** stdout is the protocol channel; a stray `console.log` corrupts it. Documented alongside the esbuild no-runtime-`fs` constraint.
- **sdk-proxy:** credits are scaled ×100 exactly once, here — the counterpart to the engine's ACME ×1e8.

### Deviation

The runbook proposed dropping the rules from `AGENTS.md` and relying on `llms-full.txt`. Instead they moved into `llms.txt` verbatim under `## Rules`, because `llms.txt` is the router an agent loads first and the 1e8 rule is the single most valuable sentence in the corpus. A cross-reference was added in both directions so each file points at the other's genre.

### Not done

Hosting `llms.txt` at a domain root (so agents can find `/llms.txt`) remains Phase 4 work.
