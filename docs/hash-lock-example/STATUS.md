## Decisions
- D-05 2026-10-16: In the hash-lock flow, `fund_sender` (D-1 step 10) and ANY step whose principal is the lite token account after `create_identity` carries an explicit `signerUrl: '{{generate_keys.liteIdentity}}'`. Why: the generator signs every post-CreateIdentity transaction (except CreateIdentity/AddCredits) with the ADI `book/1`, which is not an authority of a lite account, so the tx stays `pending` forever (P2-F3; found live in all five languages). Alternative rejected: changing the shared injection rule (would touch every flow).
- D-03 2026-10-16 (USER INSTRUCTION in conversation, supersedes RUNBOOK P7.3 and MASTER_PROMPT §7.2/Definition of done): the release criterion is **2 consecutive successful published-SDK runs per language** (was 3), "to increase progress velocity". Everything else in P7 is unchanged: local-SDK run, independent verification JSON for every run, wrong-preimage negative check per language, one retry per failed run with the cause recorded. RELEASE-READINESS.md must state "2 runs" and cite this decision.
- D-04 2026-10-16 (scope trims; user was told, did not object, and chose only item 3 above): (a) the optional "recommended SDK branch fixes" in P1.3 are NOT done: no `htlc-fixes` branches are created; each Appendix C defect is resolved as a template workaround or recorded as a follow-up for the SDK owners. (b) the D-02 Rust-harness warm-up fix is NOT done as a suite change (reverses D-02's plan). Consequence, to be stated in RELEASE-READINESS.md: `rust-validation.test.ts` still silently skips its compile and mock-execution tests, so Rust enforcement for `hash-lock` is verified manually (generate the bin, `cargo check --bin hash_lock`, run the mock harness) with the output saved as evidence, not by the suite. (c) no `/code-review` pass beyond what P9 strictly needs is added; P9 step 3 stays because MASTER_PROMPT §7.5 requires it unless the user waives it.
- D-02 2026-10-16 (SUPERSEDED by D-04b): Treat B-3 (rust-validation warm-up false green) as in scope. P2 step 2 and P5 step 4 literally require the `*-validation` suites to compile and mock-execute generated code, so a suite that silently skips Rust cannot satisfy them. Fix = make the warm-up check the self-contained bins only (or `cargo fetch` + a single known-good `--bin`), keep the skip for a genuinely absent toolchain, and fail loudly when a self-contained bin does not compile. Not a weakening of any test: it removes a silent skip. Alternatives rejected: leave as is (false green) · delete the partial bins (not ours to delete).
- D-01 2026-10-16: Fix the baseline lockfile drift before anything else — `npm ci` failed on a clean checkout (`package-lock.json` lacked `pyright@1.1.414` and `typescript-language-server@5.3.0`, which root `package.json` declares via the agent-lsp commits), so every baseline gate except the two dependency-free validators was unrunnable. Separate commit `Sync package-lock for pyright and typescript-language-server so npm ci works` (pre-existing defect, not HTLC work). Alternatives rejected: waiving (blocks all gates) · committing the full npm-11 rewrite (noisy, unrelated).
